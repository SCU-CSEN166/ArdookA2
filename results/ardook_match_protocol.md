# Ardook grant-match classifier: protocol (written before training)

Committed before any model in `src/match_classifier.py` was trained. Results are in
`results/ardook_match_v1/`; this file is not edited after training except for the
"Deviations" section at the end.

## Data used and excluded

| Source | Used for | Notes |
| --- | --- | --- |
| `data/ardook_extra_synthetic_data.db` (clean synthetic) | training, validation, test | 200 fictional applicants x 150 fictional grants = 30,000 rule-labelled pairs |
| `Ardook_data.xlsx`, sheet *Grant Tracker* | Ardook training (dev part) and evaluation (held-out part) | 37 real grants, one applicant (Ardook) |
| `data/ardook_messy_synthetic_data.db` and its generator | **never** | not opened by any new code; a test enforces this |
| `data/ranking_review/` | not used | 160 pairs, but no completed human reviews exist |
| `week8_hidden_test/` labels | not used for training, selection or thresholds | may be scored once after the model is frozen |

## Target

Binary: `match` versus `not_match` for one (applicant, grant) pair.

* Synthetic: `match` -> `match`; `unrelated` and `ineligible` -> `not_match`. The original
  3-way label is kept for error analysis. These labels are generated by rules (shared focus
  and no known rule violation; missing applicant facts tolerated; deadlines ignored), so
  `match` does not establish eligibility.
* Real tracker `Fit` (a relevance/priority judgement written for Ardook, not verified
  eligibility): `Excellent`, `Strong` -> `match`; `Moderate`, `Weak–Moderate` -> `not_match`.
  Every conditional or range rating (`Strong if …`, `Excellent only if nonprofit`,
  `Moderate–Strong`, `Strong thematic fit; low practical fit`, …) is **ambiguous**: it is
  never trained on or scored, but its prediction is reported.

## Ardook evaluation profile (provisional)

Taken verbatim from the README, not confirmed by Ardook:

> Ardook is an early-stage, woman-led U.S. startup building AI, physical-AI and data products with a social-impact mission.

Structured facts, in the synthetic vocabulary: `region = US`, `woman_led = yes` (both stated in
the sentence). `entity_type` (startup does not confirm for-profit vs nonprofit) and
`annual_revenue` are **unknown** and omitted, the same way the synthetic data marks missing facts.

## Features (allowlist)

Applicant: description + structured facts. Grant: `Program`, `Type`, `Core Requirements`,
`Amount / Benefit` only. Never used: `Fit`, `Why It Fits Ardook Data`,
`Key Concern / Disqualifier`, `Recommended Action`, `Applied?`, deadline/status, URLs, IDs,
row numbers, the synthetic `Focus` column, the synthetic rules table, any label.

## Splits

* Synthetic, seed 42, about 60/20/20. Applicants are grouped by description text (108 groups,
  so the same wording with different facts never crosses splits); grants are grouped by
  requirement text with numbers removed. A pair is kept only when applicant and grant fall in
  the same split.
* Real: the 28 unambiguous grants are grouped into families (all Google / Google.org /
  Hello Alice + Google programmes form one family) and split by a seeded, label-stratified
  group split into **dev** (about two thirds, used for training and cross-validation) and
  **held-out test** (about one third, scored once at the end).
* Overlap between real grants and synthetic grants (the generator copies some phrases from the
  workbook) is measured and reported.

## Candidates and selection

Baselines: always-`not_match`, always-`match`, keyword overlap. Models: TF-IDF pair features +
logistic regression; frozen sentence encoders (MiniLM-L6, MPNet, BGE-large; local cache only)
with pair features + logistic regression, and similarity/bag-of-words features + gradient
boosting. Each model is trained on synthetic train only, and again with the real dev grants
added (their total weight fixed in advance at 10% of the synthetic training weight; evaluated
by grouped cross-validation over real dev families).

Selection score = mean of synthetic-validation macro-F1 and real-dev (out-of-sample) macro-F1.
The decision threshold is chosen on the same score. Neither the synthetic test split nor the
real held-out grants are used until the selection is frozen, and each is scored once.

## Success criteria (fixed before training)

1. **Leakage:** every automated split and feature check passes.
2. **Synthetic test:** the selected model's match recall is at least 0.50, and its match F1 is
   at least that of the TF-IDF + logistic regression and MiniLM-L6 + logistic regression
   baselines from this run.
3. **Ardook held-out grants:** macro-F1 above always-`match`, always-`not_match` and keyword
   overlap; match precision above the held-out share of `match` grants. With about ten grants
   this is weak evidence and is reported with exact counts.
4. **Engineering:** saved model reloads with identical probabilities; the CLI scores new
   applicant/grant input and the real tracker; tests pass.

Meeting these criteria would not establish real-world accuracy.

## Deviations

1. **Two-stage candidate added before the frozen run (dev data only).** A smoke run of two
   pre-registered candidates scored only about 0.65 synthetic-validation macro-F1. Diagnosis on
   synthetic validation showed that "shared focus" is easy to learn from word pairs (relatedness
   AUC 0.995) while frozen-encoder similarity barely separates it, and that requirement conflicts
   are a separate problem (AUC about 0.93). So four `twostage:*` candidates were added:
   P(match) = P(shared focus) x P(no requirement conflict | shared focus), each a logistic
   regression on hashed word-pair features (applicant word x grant word; applicant fact x
   requirement word), optionally with encoder similarities. The stage targets come from the
   synthetic 3-way label; real Ardook grants count as shared-focus, and their binary target
   trains the second stage. Regularization (C = 0.1 and 1.0) was chosen on synthetic validation.
   No synthetic test pair or held-out real grant was used for this.
2. The smoke run wrote its outputs to a scratch folder only; its numbers are not reported.
